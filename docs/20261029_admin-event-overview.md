# Admin event overview and archive

## Goal

Make `/admin/events` open a compact inline event overview on row/card activation. Show actual paid valid issued-ticket totals and distinct buyers, with capacity where meaningful. Provide bookings, edit, duplicate-as-draft and non-destructive archive actions. Put the archive entry point at the top right as an accessible icon beside the existing primary action. Preserve existing design and data.

## Decisions

- Reuse `#ui/...` components and existing libraries; no new dependencies. Use Europe/Berlin for all displayed timestamps and datetime inputs, retain UTC persistence and date-only values.
- Count paid issued tickets only when they remain valid according to existing ticket/order cancellation semantics. Do not count reservations, pending payments or cancelled tickets. Count a buyer only when at least one qualifying ticket exists; deduplicate trimmed, lowercased customer email, falling back to owner user ID or order identity when absent. Buyers are purchasers, not participants.
- Retrieve overview data on demand through an admin-authorized Convex live paginated query scoped to one event. Scan every page with bounded per-page reads; display a loading state, never incomplete totals as final. Preserve native live-page splitting when cursor ranges grow, including before expensive order joins. Reuse pagination/client patterns; do not silently truncate or collect whole event histories.
- Do not add a revenue figure: persisted order data does not provide authoritative refund-adjusted revenue. Avoid misleading financial totals; keep the overview focused on the requested ticket and buyer counts.
- Archive changes event lifecycle visibility without deleting event, tier, order, ticket, payment or accounting records. The archive icon opens an archive-only list, including legacy soft-archived events. Normal/public lists continue hiding archived/deleted records. Preserve admin archive detail/history access and permit duplication from retained archives without reviving the source or enabling invalid edits. No hard-delete or unsolicited restore feature.
- Duplicate in one authorized mutation to a fresh draft event and fresh tier keys. Copy editable event/ticket configuration, but not orders, buyers, payments, sold/reserved counters, activation-code inventory, deletion markers or source database identifiers. Keep source records unchanged.
- Use shared Valibot operation contracts or thin derived adapters for Convex/client/HTTP inputs. Expose new public operations through Convex live functions, the Hono API, TS client exports, and catalog-driven CLI/MCP. Record any necessary deviation with its reason here.
- Work only in `/tmp/opencode/eventoren-worktree.C0oic5`, a separate mktemp git worktree checked out on existing `main`; no new branches. Root checkout must not be changed during implementation. Both checkouts share the branch ref, so final integration must preserve root changes and synchronize its files/index using a checked two-tree merge only after checking for overlaps and concurrent edits; never reset or clean user work.
